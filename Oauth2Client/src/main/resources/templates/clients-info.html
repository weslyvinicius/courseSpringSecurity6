📋 Clientes OAuth2 Configurados

🔗 Endpoint do Authorization Server:

POST http://localhost:8080/oauth2/token

Grant Type: client_credentials

📡 API Client

Cliente principal para acesso a APIs com permissões completas.

Client ID: api-client
Client Secret: api-secret
Scopes: read write admin
Token TTL: 1 hora
📋 Exemplo de Requisição cURL:
curl -X POST http://localhost:8080/oauth2/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -H "Authorization: Basic $(echo -n 'api-client:api-secret' | base64)" \
  -d "grant_type=client_credentials&scope=read write admin"

🧪 Test Client

Cliente para testes com escopo limitado e TTL reduzido.

Client ID: test-client
Client Secret: test-secret
Scopes: test
Token TTL: 30 minutos
📋 Exemplo de Requisição cURL:
curl -X POST http://localhost:8080/oauth2/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -H "Authorization: Basic $(echo -n 'test-client:test-secret' | base64)" \
  -d "grant_type=client_credentials&scope=test"
🚀 Testar este Cliente

⚠️ Informações Importantes:

  • Segurança: Nunca exponha o client_secret em aplicações client-side!
  • Ambiente: Esta configuração é apenas para desenvolvimento - use passwords criptografadas em produção!
  • Scopes: Definem as permissões que o token terá ao acessar recursos
  • TTL: Tempo de vida do token - após expirar, um novo token deve ser solicitado

🎯 Como usar os tokens obtidos:

# Exemplo de uso do token em uma API protegida
curl -X GET https://sua-api.com/api/recursos \
  -H "Authorization: Bearer SEU_ACCESS_TOKEN_AQUI" \
  -H "Content-Type: application/json"
